# shine_kiosk

교회 카페 주일 점심 셀프 주문 키오스크. 주문받는 사람 없이 만드는 사람 3명만으로 운영하기 위한 시스템.

- **고객 태블릿**: `http://localhost:8080/kiosk` — 메뉴 → 장바구니 → 받는 방법 → 결제 → 이름 → 완료
- **스태프 폰** (기록·설정 포함): `http://<태블릿 IP>:8080/staff` — PIN 로그인 후 실시간 주문 목록 (완료/수정/취소), 쿠폰 등록/충전

## 구조

```
server/   Spring Boot 4 · Java 21 · SQLite (JdbcClient, JPA 없음) · WebSocket
client/   React 19 · Vite · TypeScript  (/kiosk, /staff 두 화면이 한 앱)
```

`./gradlew bootJar` 한 번이면 프론트를 빌드해서 jar 안에 넣고 `server/build/libs/kiosk-server.jar` 하나가 나온다.
태블릿에는 이 파일 하나만 옮기면 된다.

## 개발

```sh
# 서버 (8080)
./gradlew :server:bootRun

# 프론트 개발 서버 (5173, /api 와 /ws 는 8080 으로 프록시)
cd client && npm install && npm run dev
```

DB 파일은 `./data/kiosk.db` 에 자동 생성된다. 스키마는 매 기동마다 실행되지만 `IF NOT EXISTS` 라 데이터가 지워지지 않고,
나중에 추가된 컬럼은 `SchemaMigration` 이 기동 때 붙이므로 기존 DB 를 지우지 않고 jar 만 바꿔도 된다.
메뉴·옵션(샷 추가/연하게)·배달 장소는 **스태프 화면 > 설정** 에서 관리한다 (품절/판매중, 가격, 선택지, 순서, 추가/삭제).
옵션은 카테고리 단위로 붙는다 (기본: 커피에만 샷 추가 +500원, 연하게). 무료 1잔은 옵션까지 더한 값으로 가장 비싼 한 잔을 고른다.
`seed-menu.sql` / `seed-places.sql` 은 처음 설치해서 테이블이 비어 있을 때 한 번만 들어가는 기본값이다.

## 테스트

```sh
# 서버 API 테스트 (JUnit + MockMvc, 임시 SQLite). 인증/메뉴/쿠폰/주문/스태프 처리 전 분기
./gradlew :server:test

# 브라우저 E2E (Playwright, 설치된 크롬 사용). jar 를 8091 에 임시 DB 로 띄우고 키오스크/스태프 화면을 실제로 조작
./gradlew bootJar && cd client && npm run e2e
```

E2E 는 태블릿(800×1333)과 폰(412×915) 뷰포트로 돈다. 실패하면 `client/test-results/` 에 스크린샷이 남는다.

## 설정 (PIN, 계좌)

실제 값은 **`config/application.yml`** 에 넣는다. git 에 올라가지 않는 파일이고, 서버를 실행하는 폴더의 `config/` 안에 있으면 자동으로 읽힌다.

```sh
cp config/application.example.yml config/application.yml   # 그 다음 값을 채운다
```

```yaml
kiosk:
  staff-pin: "0000"                            # 스태프 화면 PIN 4자리
  bank-account: "국민 123-45-678901 (열린교회)"  # 계좌이체 화면 안내 문구
```

환경변수로도 줄 수 있고(파일보다 우선), 둘 다 없으면 `server/src/main/resources/application.yml` 의 기본값이 쓰인다.

| 설정 | 환경변수 | 기본값 | 설명 |
|---|---|---|---|
| `kiosk.staff-pin` | `KIOSK_STAFF_PIN` | `1234` | 스태프 화면 PIN — **운영 전에 반드시 바꿀 것** |
| `kiosk.bank-account` | `KIOSK_BANK` | (안내 문구) | 계좌이체 화면에 그대로 보임 |
| `kiosk.db-path` | `KIOSK_DB` | `./data/kiosk.db` | SQLite 파일 경로 |
| `kiosk.backup-dir` | `KIOSK_BACKUP_DIR` | `./backups` | DB 자동 백업 폴더 (기동 시 + 매일 04:00, 최근 10개 유지). 태블릿은 다운로드 폴더 |
| `server.port` | `KIOSK_PORT` | `8080` | 서버 포트 |

## 결제 규칙

- 결제 수단은 계좌이체 / 쿠폰 / 현금 세 가지.
- **쿠폰**은 선불 잔액. 주문 금액 **전액**이 잔액에서 빠지고, 잔액이 모자라면 잔액을 다 쓰고 나머지는 현금/계좌이체.
- 20,000원 충전마다 **무료 1잔**이 적립된다. 고객이 쿠폰 화면에서 "무료 1잔 쓰기"를 체크하면
  그 주문에서 가장 비싼 한 잔 값이 먼저 빠지고 나머지만 잔액에서 차감된다.
- 쿠폰 조회는 이름으로. 같은 이름이 둘 이상일 때만 전화번호 뒤 4자리를 묻는다.
- **잔 단위 커스텀**: 장바구니의 칩(샷 추가 / 연하게 / 사역자)은 한 번 누를 때 **한 잔**만 바뀐다 (2잔 중 1잔만 샷 추가 등).
- **사역자 무료**: 잔에 "사역자" 를 체크하면 그 잔은 0원. 누구인지는 묻지 않는다. 낼 금액이 0 이면 결제 없이 이름만 받고 접수(결제 수단 NONE).
  쿠폰 무료 1잔은 돈 내는 잔 중에서만 고른다.
- 배달은 **1층만** (식당/전도사님실). 2층 이상은 만드는 사람이 자리를 비워야 해서 하지 않는다.
- 계좌이체는 확인 절차 없이 계좌를 보여주고 다음으로 넘어간다 (신뢰 기반). 외상은 없다.
- 스태프가 주문을 취소하거나 수정하면 쿠폰 차감(무료 1잔 포함)은 자동으로 되돌리고 다시 계산한다.
- **수정 후 차액**: 주문 때 실제 받은 현금/이체를 기억해 두고, 수정으로 금액이 달라지면 카드에
  "500원 돌려주기" (현금으로 주거나, 주문자 쿠폰이 있으면 잔액에 넣기 — 쿠폰 주문이면 그 쿠폰, 현금 주문이면 이름으로 찾음)
  / "현금·계좌이체 N원 더 받기" 를 빨갛게 띄운다.
  처리한 뒤 버튼을 누르면 사라진다.
  카드에는 "수정됨 시각 · 이전: …" 이 남고, 취소 확인창에도 돌려줄 금액이 나온다.
- 잘못 등록/충전한 쿠폰은 스태프 화면에서 삭제하거나 잔액·무료잔 개수를 정정할 수 있다.
- 쿠폰에 전화번호를 넣어 두면, 스태프가 쿠폰 주문을 **완료** 할 때 스태프 폰의 문자 앱이 잔액 안내가 채워진 채 열린다
  (보내기만 누르면 됨). 서버는 인터넷이 필요 없고, 전체 번호는 스태프 화면에만 보인다. 완료 탭에서 다시 보낼 수도 있다.

## 백업

- 서버가 기동할 때와 매일 04:00 에 `backup-dir` 로 DB 를 복사한다 (태블릿에선 내 파일 > 다운로드 > kiosk-backups).
  DB 파일이 깨지는 경우엔 이걸로 되돌리면 되지만, **태블릿이 고장 나면 이 폴더도 같이 사라진다.**
- 그래서 스태프 화면 > 기록 > **백업 내려받기** 로 스태프 폰에 DB 를 저장해 둔다. 한 달에 한 번이면 충분하다.
- 복원: 받은 `.db` 파일을 `~/kiosk/data/kiosk.db` 에 덮어쓰고 서버 재시작.
- 주문은 키오스크가 붙인 요청 번호로 한 번만 접수되므로, 와이파이가 끊겨 다시 눌러도 중복되지 않는다.
